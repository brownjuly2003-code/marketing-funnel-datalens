# Будущий дашборд DataLens

В ClickHouse источником канальных карточек служит `channel_metrics`, одна строка на сочетание модели и канала за весь снимок. Для детализации до подписки используйте `attribution`. Датасеты и карточки предстоит создать в DataLens. [Подготовка источника](../README.md#витрина-в-clickhouse)

| Карточка | Данные | Правило |
|---|---|---|
| Подписки по каналам | conversions | Выбрана ровно одна модель; нельзя суммировать разные модели |
| Расходы, выручка, себестоимость, маржа | целые поля *_cents | В интерфейсе делить на 100, суммы хранить в копейках |
| CPA | spend / conversions | Делить агрегаты после фильтрации; не усреднять готовые CPA |
| Сравнение моделей | model × channel × conversions | Общая сумма подписок одинакова, доли меняются |
| Воронка | `user_funnel.step`, `user_funnel.users` | Сортировка по `step_number`. Ожидаемый результат по пользователям — 120 → 99 → 75 → 58 → 37 |
| Доля без атрибуции | unattributed / все подписки | Показывать явно; нулевой CPA этого канала не интерпретировать как эффективность |

Для канальных карточек задайте единичный выбор модели и фильтр канала. В таблице `attribution` отбирайте период по UTC-времени подписки `converted_at` после расчёта по полной истории касаний. Для CPA и маржи по филиалу или дню потребуются расходы с такой же детализацией.

При подключении в DataLens выберите базу загруженного снимка. Для модели `last_click` в таблице каналов должны получиться 14 подписок у search, 14 у social, 9 у display и 7 без атрибуции. При выборе email ожидаются 0 подписок, пустой CPA и маржа −100 ₽. [Эталон](runs/2026-10-31-synthetic/report.json) · [Сверка в ClickHouse](runs/2026-11-18-clickhouse.md)

## Заказы AgentFlow по филиалу и периоду

Для карточки «Заказы» используйте отдельный датасет ClickHouse. В AgentFlow (`250623a`) снимок `rv.bv_order_canonical_mat` хранит филиал в `branch` и время заказа в `order_date` типа `DateTime64(3)`. Загрузчик обновляет снимок по филиалам. Перед сверкой в интерфейсе уточните, за какой период загружены заказы. [DDL снимка, копия из AgentFlow `250623a`](../tests/fixtures/agentflow/bv_order_canonical_mat.sql) · Загрузчик — `warehouse/agentflow/dv2/business_vault/load_bv_order_canonical_mat.sh` в репозитории AgentFlow на том же коммите (в этот проект не копировался; порядок загрузки описан в комментарии к DDL).

1. В подключении к ClickHouse AgentFlow создайте SQL-датасет из запроса по дням. Результат содержит одну строку на филиал и календарный день. В подсчёт входят заказы с заголовком любого статуса, включая отменённые. При отсутствии заголовка загрузчик записывает `NULL` в `header_source`; фильтр в запросе исключает такие записи до группировки. [SQL датасета](../sql/datalens/agentflow_orders_daily.sql)
2. Оставьте `branch` строковым измерением и задайте селектор «Филиал» по этому полю. В модели предусмотрены коды `msk`, `spb`, `ekb`, `dxb`, `ala`. Для селектора «Период» используйте диапазон дат по `order_day`. Коды филиалов перечислены в схеме dbt `warehouse/agentflow/dv2/dbt/models/marts/schema.yml` репозитория AgentFlow (`250623a`); в этот проект файл не копировался.

   **Допущение о часовом поясе.** `order_day` считается как `toDate(order_date)`. У столбца `order_date` тип `DateTime64(3)` без явного часового пояса, поэтому граница дня берётся из часового пояса сервера ClickHouse. В проверке пояс контейнера ClickHouse не задавался. В прогоне 18.11 он не записывался; с 19.11 тест печатает `SELECT timezone()`, и тестовый контейнер ответил `UTC` ([протокол](runs/2026-11-19-second-audit.md)). Результат проверки от пояса не зависит, потому что время вставлено строками в поясе сервера. Допущение: на сервере AgentFlow действует тот же пояс, в котором нужны дни отчёта. Перед сверкой карточки проверить пояс сервера запросом `SELECT timezone()`; если он другой, заказы около полуночи попадут в соседний день. SQL датасета не менялся.
3. Для показателя на карточке укажите `SUM([orders])`. Свяжите оба селектора с этой карточкой. Карточки CPA и маржи используют другой датасет, где расходы заданы только по каналам за весь снимок.

Для отчёта за **полные месяцы** в AgentFlow уже есть `marts.branch_pnl`. Используйте `branch`, `month` (первое число месяца) и сумму `orders`. Чтобы отобрать, например, с 31 января по 1 февраля включительно, используйте дневной датасет. Роль `dv2_analyst` по SQL AgentFlow имеет `SELECT` на обе таблицы. Права конкретного подключения проверяются при подключении. [Модель витрины, копия из AgentFlow `250623a`](../tests/fixtures/agentflow/branch_pnl.sql) · Права — `warehouse/agentflow/dv2/governance/02_grants_analyst.sql` в репозитории AgentFlow на том же коммите (в этот проект не копировался).

При сверке выберите одинаковые месяцы с датированными заказами в обоих датасетах. Если в снимке есть заказ без заголовка, месячная модель может включить его в январь 1970 года по значению `order_date` по умолчанию. Дневной запрос учитывает только заказы с известным заголовком.
