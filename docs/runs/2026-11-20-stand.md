## Сверка чисел

Скрипт `stand/datalens_stand.py` читал числа из DataLens через data API (`POST /api/data/v2/datasets/{id}/result`), а не из ClickHouse напрямую:

- датасет `channel_metrics` с фильтром `model = <модель>` для каждой из трёх моделей: подписки, выручка, себестоимость, расходы, маржа в рублях и CPA по пяти каналам — 15 строк;
- доля подписок без атрибуции для каждой модели — 3 значения;
- датасет `user_funnel` — 5 шагов воронки.

Эталон — [report.json](2026-10-31-synthetic/report.json): те же значения 18.11 пересчитал SQL на сервере ClickHouse ([протокол](2026-11-18-clickhouse.md)). Сравнение делала функция `compare` из `src/marketing_funnel/stand_check.py`. Итог в `comparison.txt`: `compared: channel rows 15, models 3, funnel steps 5`, `NUMBERS MATCH the reference report`.

При оформлении протокола `numbers.json` сверен с `report.json` ещё раз отдельным скриптом. Сверялись все 15 строк и шесть показателей, рубли переводились в копейки. Расхождений нет. Примеры:

| Модель | Канал | Подписки | Выручка, ₽ | Маржа, ₽ | CPA, ₽ |
|---|---|---|---|---|---|
| last_click | display | 9 | 45 841,00 | 24 430,69 | 86,87 |
| last_click | email | 0 | 0 | −100,00 | пусто |
| linear | search | 10,5 | 39 765,00 | 21 092,58 | 74,11 |
| time_decay | social | 16,43 | 68 508,43 | 37 224,47 | 27,71 |

В каждой модели выручка по каналам в сумме 190 185,00 ₽, маржа — 102 486,58 ₽. Это 19 018 500 и 10 248 658 копеек, как в протоколе 18.11. Доля без атрибуции во всех трёх моделях равна 7 / 44 ≈ 0,159: неатрибутированные подписки ни одна модель между каналами не делит. Воронка: 120 → 99 → 75 → 58 → 37.

Карточки строил движок `/api/run`. Каждая вернула HTTP 200 и непустой список `data.rows`: «Каналы выбранной модели» с параметром `model = last_click` — 5 строк, «Доля без атрибуции» — 1, «Сравнение моделей» — 15, «Воронка» — 5 (`api/21`–`24` в `logs.zip`).

| 2 | Следующий прогон: ClickHouse ответил ошибкой Code 164 | Профиль `readonly` не даёт менять настройки, а DataLens передаёт с каждым запросом `join_use_nulls`, `readonly`, `send_progress_in_http_headers` и `output_format_json_quote_denormals` | Свой профиль `datalens_readonly` с теми же значениями в [datalens.xml](../../stand/clickhouse/users.d/datalens.xml); тест `test_clickhouse_profile_allows_the_settings_datalens_sends` | `9f4e5ca` |
| 3 | Следующий прогон: сервер дашбордов отклонил дашборд | Связи (connections) ссылались на id виджетов, а `datalens-ui` (`src/server/components/sdk/dash.ts`) принимает только id селекторов и id вкладок виджетов | Связи ссылаются на вкладки виджетов; тест `test_dashboard_connections_name_the_control_and_widget_tabs` | `9f4e5ca` |
| 4 | Четвёртый прогон прошёл: числа, карточки, снимки. ## Что прогон не доказывает

- Подключение к ClickHouse из AgentFlow и селекторы по филиалу и периоду на стенде не проверялись. Для заказов AgentFlow есть отдельный SQL, он проверен только на контрольных данных ([README](../../README.md#ограничения-и-следующий-этап), [протокол](2026-11-18-agentflow.md)).
- Вручную в интерфейсе DataLens никто не работал. Числа прочитаны через data API, карточки собраны через `/api/run`, а интерфейс проверен снимками, сделанными скриптом в Chromium.
- Селектор канала на дашборде не создавался и не проверялся: есть только селектор модели.
- Прогон один, на одной машине и при уже скачанных образах. Время холодного старта и пиковая память не измерены.
- Данные синтетические; стенд учебный, без авторизации, temporal и демо-данных.
